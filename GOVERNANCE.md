# Project governance

Morph is an open-source, entity-driven Backend-as-a-Service.

## Roles

| Role | Responsibility |
|------|----------------|
| **Maintainer** | Merge rights, release decisions, CoC enforcement, security triage |
| **Contributor** | Anyone submitting issues, PRs, docs, or discussions under project norms |
| **User** | Runs Morph; feedback via issues is welcome |

## Decision making

- Day-to-day technical choices: PR review consensus among maintainers.
- Cross-cutting or breaking design: open an issue, and for durable decisions add
  or update an ADR under `docs/adr/`.
- Security: handled privately per [SECURITY.md](SECURITY.md); public disclosure
  after a fix or agreed timeline.

## Collaboration policy (summary)

Full detail lives in [CONTRIBUTING.md](CONTRIBUTING.md):

1. Be respectful — [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) applies everywhere.
2. Discuss non-trivial features before large PRs.
3. Keep changes focused; include tests for behavior changes.
4. Apache-2.0 for code and contributions.
5. No secrets in the repository.

## Roadmap ownership

Maintainers set near-term priorities. Community RFCs via issues are encouraged;
acceptance is not guaranteed until a maintainer commits to shepherding the work.
